## Важное требование

Adapter и Facade решают разные задачи.

- **Adapter** преобразует один интерфейс в другой.
- **Facade** предоставляет более простой интерфейс к подсистеме.

Не следует объединять их в один класс только потому, что оба используются в одной лабораторной работе.

## Описание решения

В ходе лабораторной работы была выполнена интеграция существующего компонента (аналоговых часов) в новую систему с применением паттернов проектирования **Adapter** и **Facade**. 

Хотя оба паттерна используются в одной подсистеме, они решают принципиально разные задачи.

### 1. Паттерн Adapter (Адаптер)
**Задача:** Обеспечить совместную работу объектов с несовместимыми интерфейсами.

**Реализация в проекте:** 
Исходный класс `AnalogClock` хранит время в виде углов поворота стрелок (float) и признака времени суток (`DayNightDivision`), в то время как клиентский код ожидает работу с объектами `datetime` (интерфейс `BaseDigitalClock`). 
Для решения этой проблемы был создан класс `DigitalClockAdapter`:
*   Он реализует интерфейс `BaseDigitalClock`.
*   Внутри (через композицию) он использует объект `AnalogClock`.
*   При установке времени (`set_date_time`) он разбирает `datetime` на часы, минуты, секунды, вычисляет соответствующие углы стрелок (учитывая AM/PM) и передает их в `AnalogClock`.
*   При получении времени (`get_date_time`) он считывает углы, выполняет обратное математическое преобразование и собирает их обратно в `datetime`.

**Итог:** Adapter выступил в роли «переводчика», преобразовав несовместимый интерфейс аналоговых часов в нужный клиенту цифровой интерфейс, при этом мы не изменяли публичный интерфейс `BaseAnalogClock`.

### 2. Паттерн Facade (Фасад)
**Задача:** Предоставить простой, высокоуровневый интерфейс к сложной подсистеме, скрывая детали её работы.

**Реализация в проекте:**
Подсистема часов состоит из нескольких компонентов: `DigitalClockAdapter` (для работы с часами), `ClockFormatter` (для красивого вывода строки) и `ClockHistory` (для ведения лога изменений). Если бы клиент работал с ними напрямую, ему пришлось бы вручную создавать все эти объекты и связывать их вызовы.
Для инкапсуляции этой сложности был создан класс `ClockFacade`:
*   Он скрывает внутри себя инициализацию адаптера, форматтера и истории.
*   Он предоставляет клиенту всего 4 простых метода: установить время, получить время, получить отформатированную строку и получить историю.
*   Фасад не содержит бизнес-логики — он лишь делегирует (передает) вызовы нужным компонентам подсистемы.

**Итог:** Facade упростил работу клиентского кода (файл `app.py`), изолировав его от деталей реализации подсистемы.

### Главное отличие
*   **Adapter** меняет интерфейс одного объекта на другой, чтобы они стали совместимы (цель — **совместимость**).
*   **Facade** не меняет интерфейсы, а объединяет работу нескольких классов за одним удобным интерфейсом (цель — **упрощение**).
